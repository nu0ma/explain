撮影がボトルネックだった。Chromeを分けて並列に撮り、変わらないフレームは撮らないようにした。

## A 結論 {span=3}
```callout ok 撮る枚数と撮り方を変えた
1つのChromeでは撮影が並列にならない。そこでChromeを4つに分けた。さらに、画面が変わらないフレームは前の画像を使い回し、撮る枚数を約6分の1にした。
```

## B 書き出しの流れ {span=2}
```flow LR
@player[プレイヤーのページ] -> @tabs[撮影するタブ]: 時刻を指定して描く
+@keys[変わる範囲の一覧] -> tabs: 撮るフレームだけ選ぶ
tabs -> @jpeg[JPEG]: 撮影
jpeg -> @ffmpeg[ffmpeg]: 順番に並べて渡す
ffmpeg -> @mp4[(MP4)]
group Chrome 4つ: tabs
```
緑のノードは今回足した仕組み。

## C 時間の内訳
```limits
変更前 | 48.6 / 48.6 | 秒
Chromeを4つに分けたあと | 26.7 / 48.6 | 秒
すべて入れたあと | 16.3 / 48.6 | 秒
```
同じ84秒の動画で、音声はキャッシュ済みの状態で`video --mp4`全体を測った値。

## D 何が効いたか {span=2}
| 変更 | 効果 | 備考 |
|---|---|---|
| タブを増やすだけ | warn 59→76fps | 1つのChromeでは頭打ち |
| Chromeを4つに分ける | ok 約2倍 | 1枚の撮影は約40ms |
| 変わらないフレームを省く | ok 3,211枚→569枚 | 変わる範囲をプレイヤーが返す |
| JPEGの品質を下げる | no 見送り | 画質が変わる |

## E 注意
```callout warn MP4はバイト単位では毎回同じにならない
撮る順番が毎回変わるため。違いはChromeが描くときの数ピクセルで、見た目では区別できない。
```
